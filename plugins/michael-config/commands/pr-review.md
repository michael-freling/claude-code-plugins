# PR Review Workflow

Review open pull requests in the current repository that have passing CI checks.

The main thread selects the PRs, fetches the diffs, and posts the comments. The
review analysis itself is **delegated to a subagent** — see the
`subagent-routing` skill for the full task-type table.

## Phase 1: Find PRs to Review

First, list all open PRs in the current repo:

```bash
gh pr list --state open --json number,title,author,headRefName,updatedAt
```

For each PR, check if all CI checks have passed:

```bash
gh pr checks <PR_NUMBER> --json name,state
```

Only proceed with PRs where ALL checks have state "SUCCESS". Skip PRs with pending or failing checks.

## Phase 2: Determine Review Action

For each PR with passing CI, check existing reviews:

```bash
gh pr view <PR_NUMBER> --json reviews,commits
```

**Skip the PR if:**
- A user (not `github-actions[bot]`) has reviewed AND no new commits since that review

**Review the PR if:**
- No previous reviews exist
- OR only Claude/bot reviews exist and new commits were pushed since
- OR user hasn't reviewed yet

To check for Claude's previous reviews, look for reviews containing `[Claude Code Review]` in the body.

## Phase 3: Handle Existing Claude Comments

If Claude previously reviewed and new commits exist since that review:

1. List all review comments on the PR:
   ```bash
   gh api repos/{owner}/{repo}/pulls/<PR_NUMBER>/comments --jq '.[] | select(.body | contains("[Claude Code Review]"))'
   ```

2. Get the diff for new commits since Claude's review

3. For each Claude comment:
   - Check if the code at that location was modified
   - If the issue appears to be addressed, resolve the comment:
     ```bash
     gh api -X PATCH repos/{owner}/{repo}/pulls/comments/<COMMENT_ID> -f body="[Resolved] <original comment>"
     ```
   - Or use the GraphQL API to resolve the review thread if available

## Phase 4: Analyze Changes — Dispatch a Subagent and Wait

Get the full diff for the PR:

```bash
gh pr diff <PR_NUMBER>
```

Do not perform the review analysis in the main thread. **Dispatch** it with the
`Agent` tool and wait for the result:

| PR touches | Agent |
|------------|-------|
| Application code, tests, config, docs | `michael-config:code-reviewer` |
| A GitHub Actions workflow | `michael-config:github-actions-workflow-engineer` |
| Kubernetes manifests, Kustomize, Helm | `michael-config:kubernetes-engineer` |
| An architecture, API, or DB schema change | `michael-config:architecture-reviewer` |

A PR that spans several of these takes one subagent per area, dispatched
together since the areas are independent.

The subagent's prompt is the only context it gets. Give it the PR number, the
diff, the paths of the changed files to read for full context, and the aspect
list below. Require it to report every finding as `file:line` plus a concrete
suggestion, since Phase 5 posts each one as an inline comment at that location.

Then **wait** for its findings. Do not review the same diff in parallel, and do
not re-derive its findings afterwards — Phase 5 posts what it reported.

The subagent analyzes for ALL code quality aspects:
- **Correctness**: Logic errors, bugs, edge cases
- **Readability**: Clear naming, code organization, complexity
- **Maintainability**: Code structure, coupling, cohesion
- **Performance**: Inefficient algorithms, unnecessary operations
- **Error handling**: Missing error checks, improper error propagation
- **Concurrency**: Race conditions, deadlocks, thread safety
- **Security**: Input validation, injection risks, sensitive data exposure
- **Style consistency**: Alignment with existing codebase patterns
- **Integration completeness**: When new functions, methods, interfaces, or types are added without callers, check if the PR description explains why; if not explained, ask why the new code isn't being used yet

## Phase 5: Post Review

### Inline Comments (Issues Only)

For each issue found, post an inline comment:

```bash
gh api repos/{owner}/{repo}/pulls/<PR_NUMBER>/comments \
  -f body="[Claude Code Review] <issue description and suggestion>" \
  -f commit_id="<HEAD_COMMIT_SHA>" \
  -f path="<FILE_PATH>" \
  -f line=<LINE_NUMBER> \
  -f side="RIGHT"
```

**Important**: Only post inline comments for issues that need action. Do NOT post positive/praise comments inline.

### Summary Comment

Post a summary review comment:

```bash
gh pr review <PR_NUMBER> --comment --body "$(cat <<'EOF'
## Claude Code Review Summary

### Overall Assessment
<Brief assessment of the PR quality>

### What's Done Well
<Positive feedback - things that are good about this PR>

### Suggestions
<List any inline comments posted, or note if none>

### Resolved Comments
<List any previously posted comments that were addressed by new commits>

---
*This review was generated by Claude Code. Note: As the PR author's assistant, I cannot approve this PR.*
EOF
)"
```

## Phase 6: Self-Review Limitation

When Claude is reviewing PRs it helped create:
- Use `--comment` review type (not `--approve` or `--request-changes`)
- GitHub API doesn't allow approving your own PR
- The summary should note this limitation

## Key Rules

1. **Only review PRs with passing CI** - Skip PRs with failing or pending checks
2. **Respect user reviews** - If a human reviewed and no new commits, skip (assume agent is working on it)
3. **Resolve addressed feedback** - When new commits fix issues Claude raised, mark as resolved
4. **No positive inline comments** - All praise goes in the summary only
5. **Comprehensive review** - Cover all code quality aspects, not just bugs
6. **Clear prefix** - All inline comments start with `[Claude Code Review]`
7. **Be specific** - Include line numbers and concrete suggestions
8. **Delegate the analysis** - Dispatch a reviewer subagent and wait for its findings; the main thread posts them, it does not derive them

## Example Workflow

```bash
# 1. List open PRs
gh pr list --state open --json number,title,headRefName

# 2. Check CI status for PR #123
gh pr checks 123 --json name,state

# 3. Get PR details including reviews
gh pr view 123 --json reviews,commits,headRefOid

# 4. Get the diff
gh pr diff 123

# 5. Post inline comment
gh api repos/owner/repo/pulls/123/comments \
  -f body="[Claude Code Review] This variable is unused and can be removed." \
  -f commit_id="abc123" \
  -f path="src/main.ts" \
  -f line=42 \
  -f side="RIGHT"

# 6. Post summary review
gh pr review 123 --comment --body "## Claude Code Review Summary ..."
```
